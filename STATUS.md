## 🔄 Реализация жизненных циклов (State Machine)

Переходы проверяются дважды: в коде сервера и триггерами PostgreSQL (прямой SQL-запрос недопустимый переход тоже не проведёт).

### Событие (`Event`)
```
[Создание] ──► DRAFT ──(Админ: Одобрить)──► ACCEPTED ──(Организатор: Закрыть)──► CLOSED
                  │                            │
                  │                            └──(Организатор / Админ: Отменить)──► CANCELLED
                  └──(Админ: Отклонить / Организатор: Отозвать)──► CANCELLED
```

### Заявка волонтёра (`VolonteerEventRequest`)
```
[Подача] ──► OPEN ──(Орг: Одобрить)──► ACCEPTED ──(Орг: Подтвердить часы)──► CONFIRMED
                │
                │                              └──(Орг: Отозвать / Волонтёр: Отказаться)──► CANCELLED
                └──(Орг: Отклонить / Волонтёр: Отозвать)──► CANCELLED
```

При отмене принятого события все его заявки в статусах `OPEN` и `ACCEPTED` отменяются триггером БД. Событие с подтверждёнными часами отменить нельзя.

## 🛠 Архитектура и стек решений

- **Frontend:** React 18, Vite 5, Leaflet; состояние — кэш `ApiStore`, данные всегда с сервера.
- **Backend:** Rust (axum 0.8, async-graphql 7, sqlx 0.8), GraphQL по адресу `/graphql`, фото — `/media/photos/{id}`.
- **База данных:** PostgreSQL 16; модель по схеме из задания (Person, Organization, Event, Volonteer, VolonteerEventRequest); перечисления, внешние ключи, `CHECK`, триггеры статусов, журнал аудита, фото в `bytea`.
- **Безопасность:** Argon2id, JWT в HttpOnly-cookie, блокировка после 5 неудач, проверка Origin, лимиты запросов, маскирование данных по ролям, рабочая роль БД с минимальными правами. Подробно — [docs/BACKEND.md](docs/BACKEND.md#безопасность-данных). Персональные данные — [docs/PRIVACY.md](docs/PRIVACY.md).
- **Контракты:** `schema.graphql` (генерируется из кода, сверяется тестом) и `operations.graphql`.
