## 📌 Разбор замечаний по пунктам

### 1. Несоответствие README реальной структуре репозитория
* **Было:** В README фигурировали не существовавшие папки `src/components`, `router`, `React/Vue`.
* **Исправлено:** `README.md` полностью переписан. Теперь он честно, подробно и профессионально отражает реальную структуру файлов, модульную архитектуру, назначение каждого скрипта (`app.js`, `data.js`, `graphql-client.js`, `operations.graphql`, `test-suite.js`), а также актуальные инструкции по быстрому запуску без лишних обещаний.

### 2. Выбор технологий (Vanilla JS vs React)
* **Позиция команды:** Для условий хакатона сжатые сроки требовали максимальной скорости отклика, отсутствия конфликтов пакетов node_modules и мгновенного запуска на любом компьютере жюри в одну команду (`node serve.js`). Выбран модульный Native ES6+ стек с собственной реактивной шиной данных (`appStore`), разделением на контроллеры представлений и нулевым оверхедом при сборке.

### 3. Ролевая модель, авторизация и JWT
* **Было отмечено:** Опасение, что любой пользователь может зайти куда угодно без защиты.
* **Что реализовано:**
  - Полный механизм авторизации по стандарту **JWT (RFC 7519)** с HMAC-подписью и сроком жизни токена (24 ч).
  - Инспектор токена в личном кабинете с декодированием `Header` и `Payload`.
  - **Авторизация по требованию (Auth-on-Demand):** для неавторизованных пользователей открыты только публичный каталог и просмотр карты. При попытке подать заявку или поставить метку система блокирует действие и открывает модальное окно авторизации/регистрации.
  - Кабинеты ролей (Администратор, Организатор, Волонтёр) динамически фильтруются и скрыты от посторонних.

### 4. GraphQL и интеграция с DataSpace Community Edition
* **Было:** Непонятно, как работает GraphQL и где описаны запросы.
* **Что сделано:**
  - Все клиентские запросы и мутации собраны в единый файл [`operations.graphql`](operations.graphql).
  - Клиент [`graphql-client.js`](graphql-client.js) расширен: реализован полноценный Mock-движок, поддерживающий выполнение всех запросов (`availableEvents`, `events`, `organizations`, `volonteers`, `requests`, `volonteerStatement`) и мутаций (`login`, `register`, `createEvent`, `moderateEvent`, `submitEventRequest`, `confirmVolunteerWork`, `closeEvent`).
  - Добавлен метод `setRemote(enabled, endpoint)` для бесшовного подключения к реальному серверу DataSpace CE при его наличии.

### 5. Автоматические тесты
* **Было:** Отсутствие тестов.
* **Что сделано:**
  - Создан тестовый модуль [`test-suite.js`](test-suite.js), запускаемый через команду `npm test`.
  - Покрыты 5 критических сценариев:
    1. Генерация, декодирование и проверка полезной нагрузки JWT токенов;
    2. Жизненный цикл события (`CREATED` -> `ACCEPTED` -> `CLOSED`);
    3. Жизненный цикл заявки волонтера (`PENDING` -> `ACCEPTED` -> `CONFIRMED`);
    4. Математический расчёт подтверждённых часов для официальной выписки;
    5. Санитизация и экранирование входных данных для защиты от XSS.
