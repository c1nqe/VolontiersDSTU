# Бэклог и открытые вопросы

Дата: 13 октября 2026 г. Ветка `dev2`. Файл ведётся по ходу работы; закрытые пункты переносятся в раздел «Сделано» в [STATUS.md](../STATUS.md).

**Масштаб проекта.** Это студенческий некоммерческий проект волонтёрского центра ДГТУ: единицы администраторов, сотни пользователей, один сервер. Поэтому задачи уровня «большой компании» (двухфакторный вход, общий ограничитель на несколько серверов, шифрование полей, Row-Level Security, собственный тайловый сервер, метрики) не планируются: они помечены «не планируем» и возвращаются в работу, только если проект вырастет. Базовая защита уже сделана (хэши Argon2id, HttpOnly-cookie, CSRF, права по ролям, журнал аудита, согласие и удаление данных).

Приоритеты: **P0** — нужно до запуска для реальных студентов; **P1** — желательно; **P2** — если будет время; **не планируем** — оставлено для истории.

## Принятые решения (чтобы не вернуться к ним случайно)

- Статусы событий и заявок — как на схеме, плюс отмена принятого (Q2): событие `DRAFT → CANCELLED | ACCEPTED → CLOSED | CANCELLED`, заявка `OPEN → CANCELLED | ACCEPTED → CONFIRMED | CANCELLED`. Старые `CREATED` и `PENDING` переименованы в `DRAFT` и `OPEN`.
- Отмена принятого события отменяет все его заявки (триггер БД). Событие с подтверждёнными часами отменить нельзя, чтобы не обнулять уже выданные часы.
- Закрытая ПСО (с фото-отчётом, согласованным админом) удаляется сразу; статусы `FOUND` и `CLOSED` для ПСО в базе не сохраняются. Обычные метки при закрытии остаются со статусом `CLOSED`.
- Администратор не может удалить собственный аккаунт через интерфейс; организатор с принятыми событиями — тоже (сначала отменить или закрыть события).
- Журнал аудита хранится 3 года; чистка — командой `purge-audit <дней>` от владельца таблицы, не менее 365 дней.
- Удаление аккаунта обезличивает данные сразу (имя, почта, телефон, билет, дата рождения), удаляет отзывы и отменяет активные заявки; подтверждённые часы остаются обезличенными.
- Подтвердить можно и 0 часов (волонтёр пришёл, но часы не засчитываются).
- Администратор может действовать от имени любого организатора и волонтёра (переключатели в шапке кабинета).
- Выход из системы и смена пароля отзывают все сессии пользователя.
- При регистрации сервер сообщает, что email уже занят (иначе пользователь не поймёт причину отказа); при входе сообщение одинаковое для неверного email и неверного пароля.
- Фото хранятся в PostgreSQL (`bytea`), перекодируются в JPEG до 1600 px.
- Фото меток ПСО публикуются после одобрения администратором (Q7); фото администратора — сразу. Отклонённое фото удаляется, причина — в журнале аудита.
- Письма ссылок (подтверждение почты, восстановление пароля): токен одноразовый, в БД только его SHA-256; сброс пароля живёт 1 час, подтверждение — 3 суток; не чаще одного письма в минуту на пользователя и вид.
- Оператор персональных данных — физическое лицо (Q8); сервер — ДГТУ (Q5).
